# Проверки пароля по пользовательскому таймеру

## Запуск и требования

XDG-автозапуск `/etc/xdg/autostart/password-notify.desktop` вызывает
`password-notify -a`. Обычный запуск без ключей делает то же самое:
настраивает один пользовательский timer и запрашивает немедленную проверку.
Нужны работающий `systemctl --user`, графический сеанс, сеансовая шина D-Bus
и приватный `XDG_RUNTIME_DIR`, принадлежащий пользователю. Запускать от root не нужно.

Программа импортирует в пользовательский менеджер DISPLAY, WAYLAND_DISPLAY,
XAUTHORITY, DBUS_SESSION_BUS_ADDRESS, XDG_RUNTIME_DIR, KRB5CCNAME и переменные
локали; отсутствующие переменные удаляются из окружения менеджера.
DISPLAY не фиксируется на :0. Для LDAP нужен действующий Kerberos-билет;
программа не получает и не продлевает его автоматически.

## Жизненный цикл

- Сервис запускает `password-notify -s` и выполняет проверку LDAP в рабочем потоке.
- Если осталось больше `warn_days` либо пароль бессрочный, процесс завершается.
  Между проверками нет процесса password-notify или постоянно работающего скрипта.
- Следующая проверка назначается через `check_interval_hours`: целое число
  часов от 1 до 720, по умолчанию 24. Неверный диапазон заменяется на 24.
- При достижении порога показываются уведомление и красный ключ в трее.
  Внешний timer останавливается; процесс остаётся с меню смены пароля.
  Встроенный таймер GTK проверяет состояние через тот же интервал.
- После успешной смены пароля выполняется повторная проверка. Если предупреждение
  больше не требуется, процесс завершается и внешний timer включается снова.
- Выход через меню, SIGINT/SIGTERM и аварийное завершение, включая SIGKILL,
  приводят к повторному включению timer через короткий вызов `ExecStopPost`
  (`password-notify -u`). Постоянного наблюдателя нет; `Restart=no`.
- При ошибке LDAP/Kerberos предпринимается попытка показать уведомление,
  процесс завершается с кодом 1; следующая попытка назначается по timer.

Используются `OnActiveSec=Nh`, `OnUnitInactiveSec=Nh` и `AccuracySec=1s`.
После завершения процесса timer запускается заново: это интервал до следующей
попытки, а не расписание по часам суток. Немедленная проверка при входе
запускается отдельно от timer.

Имена units постоянны для UID. Блокировка `$XDG_RUNTIME_DIR/password-notify.lock`
не допускает второго управляемого GUI-процесса. Повторный `-a` не перезапускает
активный сервис и не прерывает диалог смены пароля. При нескольких графических
сеансах одного UID timer и окружение менеджера общие: последний импорт окружения
влияет на последующие запуски.

## Конфигурация и изменение интервала

```ini
[general]
warn_days = 7
check_interval_hours = 24
```

Явный `-c ФАЙЛ` имеет приоритет. Без него выбирается читаемый
`~/.config/password-notify.ini`, иначе `/etc/password-notify.ini`.
Файлы не объединяются. Если выбранный файл открыть не удалось,
используются встроенные значения.

```sh
password-notify -a -c /etc/password-notify.ini
```

Явный путь преобразуется в абсолютный и с экранированием сохраняется
в ExecStart и ExecStopPost. Каждый новый процесс заново читает конфигурацию.
Для обновления runtime units повторите `-a`. Уже работающий процесс в трее
сохраняет свою конфигурацию и внутренний интервал до перезапуска.
Чтобы немедленно применить настройки и к нему, завершите сервис и запустите
приложение из графического сеанса:

```sh
systemctl --user stop password-notify-check.service
password-notify -a -c /etc/password-notify.ini
```

## Расположение units

Программа создаёт файлы:

```text
$XDG_RUNTIME_DIR/systemd/user/password-notify-check.service
$XDG_RUNTIME_DIR/systemd/user/password-notify-check.timer
```

Обычно XDG_RUNTIME_DIR — `/run/user/<UID>`. Файлы записываются при изменении
содержимого, затем выполняется daemon-reload. В сервисе используется абсолютный
путь текущего бинарника: при запуске из дерева сборки не удаляйте и не переносите
его до перенастройки через установленный `/usr/bin/password-notify -a`.

Runtime units не входят в RPM, не требуют `enable` и файлов в домашнем каталоге.
При следующем входе XDG-автозапуск повторно настраивает проверки.
Программа не включает linger и не привязывает units к graphical-session.target;
остановка пользовательского менеджера прекращает их работу.
Если менеджер продолжает работать после выхода, timer сам по себе не гарантирует
остановку при завершении графического сеанса.

## Диагностика и отключение

```sh
systemctl --user list-timers --all password-notify-check.timer
systemctl --user status password-notify-check.service password-notify-check.timer
systemctl --user cat password-notify-check.service password-notify-check.timer
journalctl --user -u password-notify-check.service
password-notify -t -d -c /etc/password-notify.ini
```

`-t` — одна проверка без GUI и управления timer. Вне периода предупреждения
нормальны сервис inactive (dead) и timer active (waiting).
При активном предупреждении сервис работает, а внешний timer остановлен.

Чтобы остановить проверки до следующего автозапуска, сначала завершите сервис,
дождитесь выполнения ExecStopPost и затем остановите timer:

```sh
systemctl --user stop password-notify-check.service
systemctl --user stop password-notify-check.timer
```

Для постоянного отключения также отключите XDG-автозапуск средствами рабочего
стола либо пользовательским desktop-файлом с тем же именем и `Hidden=true`.

## Проверки разработки

`make test` использует имитации LDAP, уведомлений и systemctl. Проверяются выход
без предупреждения, сетевые ошибки, появление трея, повторное включение timer,
единственность процесса и изменение интервала. Реальные пользовательские units
и доменные пароли тесты не меняют.
