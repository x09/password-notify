# password-notify

[English version](README.md)

Утилита для Linux, которая уведомляет об истечении срока доменного пароля и позволяет сменить пароль в средах Samba AD / Microsoft Active Directory.

## Возможности

- Получение срока пароля через LDAP/GSSAPI по Kerberos-кешу пользователя.
- Поиск доступных контроллеров через DNS SRV с предпочтением контроллеров сайта AD клиента.
- Один пользовательский таймер systemd; если предупреждение не нужно, между проверками процесс приложения отсутствует.
- Всплывающее уведомление и красный ключ в трее, когда осталось не больше `warn_days` дней либо пароль уже истёк.
- Смена пароля через Kerberos или `/usr/bin/passwd` и стек PAM данного компьютера.
- Русская и английская локализации gettext.

Рядом с иконкой в трее текст не выводится. В MATE/XFCE используется всплывающая подсказка; для AppIndicator передаются заголовок и описание значка, показ которых при наведении зависит от панели.

## Требования

Для графического режима необходимы работающая команда `systemctl --user`, графический сеанс с сеансовой шиной D-Bus и службой уведомлений, GTK 3, libnotify, клиентские библиотеки OpenLDAP, MIT Kerberos и SASL-плагин GSSAPI. Требуются корректное разрешение DNS домена, доступ к КД и действующий Kerberos-билет пользователя. Программа не получает и не продлевает билеты автоматически.

Сборке по умолчанию нужна поддержка AppIndicator; в GNOME требуется подходящее расширение трея. Для MATE/XFCE можно собрать вариант GtkStatusIcon. При `method = passwd` смена доменного пароля командой `/usr/bin/passwd` должна заранее работать в терминале пользователя.

## Сборка и установка

Простой способ - установить пакет из репозитория

```sh
apt-get update
apt-get install password-notify
```

Ниже описана сборка из исходного кода.

Зависимости для ALT Linux:

```sh
apt-get install gcc make pkg-config gettext-tools libgtk+3-devel libnotify-devel libldap-devel libsasl2-devel libkrb5-devel
apt-get install libsasl2-plugin-gssapi
# Дополнительно для стандартной сборки AppIndicator:
apt-get install libayatana-appindicator3-devel
```

Выполняйте команды в каталоге исходников. Выберите один вариант и используйте одинаковые префикс и вариант трея при сборке и установке:

```sh
# KDE/GNOME: AppIndicator
make clean
make PREFIX=/usr
# От root:
make install PREFIX=/usr
```

```sh
# MATE/XFCE: GtkStatusIcon
make clean
make PREFIX=/usr USE_STATUS_ICON=1
# От root:
make install PREFIX=/usr USE_STATUS_ICON=1
```

`make` также собирает и проверяет английский и русский MO-каталоги. В Makefile по умолчанию задан `PREFIX=/usr/local`; в примерах выбран `/usr`. Установка размещает бинарник в `PREFIX/bin`, иконки в `PREFIX/share/password-notify/icons`, переводы в `PREFIX/share/locale`, конфигурацию в `/etc/password-notify.ini`, автозапуск в `/etc/xdg/autostart/password-notify.desktop`.

Перед ручным `make install` сохраните существующий INI: эта цель перезаписывает его. В RPM конфигурация помечена `%config(noreplace)`. Сборка пакета описана в [PACKAGE_BUILD.md](PACKAGE_BUILD.md). В ALT spec `%def_without status_icon` выбирает AppIndicator по умолчанию; `--with status_icon` выбирает MATE/XFCE.

## Конфигурация

Стандартный системный файл — `/etc/password-notify.ini`. Текущий парсер использует явно заданный путь `-c`; иначе сначала пробует `~/.config/password-notify.ini`, затем `/etc/password-notify.ini`. Настройки из разных файлов не объединяются. Для явного выбора системного файла укажите `-c /etc/password-notify.ini`.

Если выбранный файл не удалось открыть, код использует встроенные значения без завершения с ошибкой. В поставляемом INI выбран LDAP (`use_ldaps = no`), а встроенное значение протокола при отсутствии читаемого файла — LDAPS.

```ini
[general]
warn_days = 7
check_interval_hours = 24

[ldap]
server_uri =
base_dn =
use_ldaps = no
skip-issuer = false

[password_change]
method = samba

[ui]
always_notify = yes
notification_urgency = normal
```

| Параметр | Назначение |
| --- | --- |
| `warn_days` | Порог предупреждения в днях; по умолчанию 7. |
| `check_interval_hours` | Целое число часов от 1 до 720; по умолчанию 24. Значения вне диапазона заменяются на 24. |
| `server_uri` | Пустое значение — поиск КД. Примеры явного адреса: `ldap://dc.example.com`, `ldaps://dc.example.com`. Схема URI имеет приоритет над `use_ldaps`. |
| `base_dn` | Пустое значение — определить по Kerberos realm, например `EXAMPLE.COM` → `DC=example,DC=com`. |
| `use_ldaps` | Протокол автопоиска: `no` — LDAP с шифрованием SASL/GSSAPI; `yes` — LDAPS/TLS и аутентификация GSSAPI без дополнительного слоя SASL sign/seal. |
| `skip-issuer` | По умолчанию `false`. Значение `true` отключает проверку цепочки сертификата и имени сервера для LDAPS. Предпочтительно доверять выпускающему УЦ. GSSAPI сохраняется. |
| `method` | `samba` — смена пароля через Kerberos; `passwd` — прямой вызов `/usr/bin/passwd` через отдельный псевдотерминал. |
| `always_notify` | `yes` разрешает повторные уведомления при последующих проверках в период предупреждения. |
| `notification_urgency` | `low`, `normal` или `critical`. Непосредственно перед истечением и после него срочность повышается. |


## Автозапуск и расписание

При графическом входе XDG-autostart вызывает `password-notify -a`. Программа передаёт окружение дисплея, D-Bus, локали и Kerberos-кеша пользовательскому менеджеру, настраивает таймер и запрашивает немедленную проверку. Обычный запуск `password-notify` выполняет то же самое. Уже активный сервис не перезапускается.

- **Предупреждать рано / пароль бессрочный:** процесс завершается, следующий запуск планируется через `check_interval_hours`.
- **Пора предупреждать:** таймер systemd приостанавливается, программа остаётся в трее, а её таймер GTK обновляет состояние с заданным интервалом.
- **Пароль изменён:** выполняется немедленная повторная проверка. Если предупреждение больше не нужно, процесс завершается, внешний таймер включается снова.
- **Трей закрыт / процесс завершён:** таймер планирует следующую проверку. `ExecStopPost` включает его и после аварийного завершения процесса.
- **Ошибка LDAP/Kerberos:** программа пытается показать уведомление об ошибке, завершается с ненулевым кодом и планирует следующую проверку. Для каждой проверки нужен действующий Kerberos-билет.

Runtime-units с постоянными именами создаёт сама программа; как файлы RPM они не устанавливаются:

```text
$XDG_RUNTIME_DIR/systemd/user/password-notify-check.service
$XDG_RUNTIME_DIR/systemd/user/password-notify-check.timer
```

Обычно `XDG_RUNTIME_DIR` — `/run/user/<UID>`. Файлы таймера в домашнем каталоге и ручной `enable` не нужны. Блокировка запрещает параллельные управляемые экземпляры с треем; диагностика `-t` независима. На UID приходится один таймер и сервис; одновременные графические сеансы одного UID используют общее окружение менеджера. Пользовательская запись автозапуска с таким же именем имеет приоритет над системной. Подробнее — [SCHEDULER.md](SCHEDULER.md).

## Использование

Выполняйте команды от доменного пользователя в его графическом сеансе:

```sh
klist
# Получить билет, если вход в сеанс его не предоставил:
kinit user@EXAMPLE.COM
password-notify -a
# Явно указать конфигурацию:
password-notify -a -c /etc/password-notify.ini
# Однократная проверка без GUI и изменения таймера:
password-notify -t -d -c /etc/password-notify.ini
```

Реализованы только короткие параметры:

| Параметр | Назначение |
| --- | --- |
| `-c FILE` | Выбрать конфигурацию. |
| `-a` | Настроить таймер сеанса и запросить проверку; режим по умолчанию. |
| `-s` | Проверка по расписанию для сервиса; завершиться, если трей не требуется. |
| `-t` | Однократная проверка срока без GUI; вывести результат и завершиться. Без смены пароля и управления таймером. |
| `-d` | Дополнительно выводить диагностику данного процесса в stderr. Журнал управляемого сервиса доступен через journal. |
| `-h` | Справка. |
| `-v` | Версия. |
| `-u` | Внутренний режим включения таймера для `ExecStopPost`; вручную обычно не используется. |

В меню трея доступны **Сменить пароль**, **Проверить сейчас**, **О программе** и **Выход**. Выход не отключает последующие проверки навсегда. Чтобы остановить проверки в текущем сеансе, сначала остановите сервис, дождитесь завершения, затем остановите таймер:

```sh
systemctl --user stop password-notify-check.service
systemctl --user stop password-notify-check.timer
```

При следующем графическом входе проверки настроятся снова.

## Поиск КД и смена пароля

Поиск получает realm из кеша учётных данных, запрашивает `_ldap._tcp.<domain>`, проверяет кандидатов и выполняет аутентификацию GSSAPI. Затем читает сведения о подсетях и сайтах AD и пробует контроллеры сайта, при необходимости сохраняя работающий резервный КД домена. Кандидаты упорядочиваются по приоритету SRV и задержке TCP. Это не полная реализация Windows DC Locator.

`method = samba` использует начальные учётные данные для `kadmin/changepw` и API смены пароля Kerberos, а не библиотеки Samba. Некоторые ошибки категории `OTHER` вызывают резервную попытку через `passwd`; ошибки аутентификации, политики и подключения — нет. Функция смены пароля через LDAP, имеющаяся в исходниках, в этой последовательности не вызывается.

`method = passwd` напрямую отвечает на запросы PAM/passwd через отдельный терминал. Доменную политику проверяет КД/PAM. Пароли передаются в памяти и терминалу, а не в аргументах командной строки; намеренно в файлы и журнал они не записываются.

## Локализация

Английский — исходный и запасной язык. Русская локаль, например `ru_RU.UTF-8`, выбирает русский перевод; действует переопределение gettext через `LANGUAGE`. Исходники находятся в `po/`, скомпилированные каталоги — в `locale/<language>/LC_MESSAGES/`. Известные ошибки Kerberos/PAM/LDAP переводятся, включая поддерживаемые сообщения политики с числовыми ограничениями из ответа сервера. Неизвестная диагностика сохраняется на исходном языке.

При запуске неустановленного бинарника держите `locale/` и `icons/` рядом с ним. Подробнее — [LOCALIZATION.md](LOCALIZATION.md).

### Перевод ответов Samba при смене пароля

Поддерживаются все ответы клиенту из [`source4/kdc/kpasswd-helper.c`](https://github.com/samba-team/samba/blob/samba-4.21.0/source4/kdc/kpasswd-helper.c) Samba 4.21. В таблице приведены шаблоны сообщений сервера и их русские переводы, включая сокращённые варианты ошибок.

| Сообщение сервера | Русский перевод |
| --- | --- |
| `No such user when changing password` | Пользователь для смены пароля не найден |
| `Not permitted to change password` | Смена пароля не разрешена |
| `Password too short, password must be at least %d characters long.` | Пароль слишком короткий. Минимальное число символов в пароле: %s. |
| `Password too short` | Пароль слишком короткий |
| `Password does not meet complexity requirements` | Пароль не соответствует требованиям сложности |
| `Password is already in password history. New password must not match any of your %d previous passwords.` | Этот пароль уже использовался. Новый пароль не должен совпадать с предыдущими паролями (число паролей в истории: %s). |
| `Password is already in password history` | Этот пароль уже использовался |
| `Password change rejected, password changes may not be permitted on this account, or the minimum password age may not have elapsed.` | Смена пароля отклонена. Возможно, для этой учётной записи запрещена смена пароля либо ещё не истёк минимальный срок действия пароля. |
| `Failed to set password: %s` | Не удалось установить пароль: %s |
| `Failed to set password` | Не удалось установить пароль |
| `Password changed` | Пароль изменён |
| `A TGT may not be used as a ticket to kpasswd` | Билет TGT нельзя использовать для обращения к kpasswd |
| `Failed to ascertain that ticket to kpasswd is not a TGT` | Не удалось убедиться, что билет для обращения к kpasswd не является TGT |

Значения `%d` (минимальная длина пароля и глубина истории паролей) поступают от сервера и не привязаны к числам 7 или 24. Приложение подставляет их в шаблоны gettext с `%s`. В сообщении `Failed to set password: %s` диагностика сервера, например `NT_STATUS_ACCESS_DENIED`, сохраняется без изменений. При английской локали ответы остаются на английском языке.

Перевод выполняет password-notify после получения ответа; изменять исходники Samba не требуется. Список охватывает ответы клиенту, а не внутренние отладочные сообщения сервера.

## Диагностика и текущие ограничения

```sh
systemctl --user list-timers --all password-notify-check.timer
systemctl --user status password-notify-check.service password-notify-check.timer
systemctl --user cat password-notify-check.timer
journalctl --user -u password-notify-check.service
journalctl -t password-notify
```

Неактивный сервис с ожидающим таймером — нормальное состояние между проверками. При предупреждении сервис активен, внешний таймер остановлен. Если `systemctl --user` не может подключиться, сначала исправьте пользовательский менеджер и интеграцию сеанса; изменение `DISPLAY` само по себе его не запускает.

Проверяйте LDAP с явным именем КД:

```sh
klist
dig SRV _ldap._tcp.example.com
ldapsearch -H ldap://dc.example.com -b 'DC=example,DC=com' -Y GSSAPI
```

Для LDAPS используйте доверенные сертификаты. Отсутствие иконки может означать, что порог предупреждения ещё не достигнут; сначала проверьте `-t -d` и журнал.

- Чтение срока зависит от атрибута AD `msDS-UserPasswordExpiryTimeComputed`. При его отсутствии код пишет предупреждение и считает пароль бессрочным; расчёта по доменной политике нет. Поддержка произвольного LDAP/FreeIPA не реализована.
- Диалог дополнительно отклоняет пароль короче восьми байт (`strlen`) до обращения к серверу; фактическую доменную политику проверяет КД/PAM.
- Учёт сайта используется как предпочтение и не гарантирует выбор географически ближайшего КД.
